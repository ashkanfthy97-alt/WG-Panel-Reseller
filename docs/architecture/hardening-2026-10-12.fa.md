- نصب تعاملی پس از نصب سرویس، تنظیم WireGuard/NAT و Telegram را پیشنهاد می‌دهد.

## اجرا و محدودیت‌ها
این سیاست‌ها در حالت --managed اعمال می‌شوند. --existing-port مالکیت پنل بیرونی را ندارد و سورس آن را تغییر نمی‌دهد.

محیط هدف: Python 3.11+؛ Debian 12+ یا Ubuntu 24.04+ پیشنهاد می‌شود.
قفل وابستگی از metadata بسته‌ها برای Python 3.12 / Linux x86_64 حل شده؛ این به معنی آزمایش اجرایی همه بسته‌ها روی همه نسخه‌های Linux نیست. بسته‌های apt و خود Python با این فایل قفل نمی‌شوند.

همان worker نوع sync پنل حفظ شده است؛ THREADS در هسته upstream گزینه مؤثر concurrency نیست. پرتال جداگانه از gthread استفاده می‌کند. این تغییر ادعای افزایش threadهای هسته ندارد.

داده‌ها در .env، instance و /etc/wireguard با patcher بازنویسی نمی‌شوند. تغییر منابع کد در صورت خطای نوشتن rollback می‌شود؛ این قابلیت جای snapshot کامل VPS یا rollback مهاجرت دیتابیس را نمی‌گیرد.

## نصب و ارتقا
از مخزن خصوصی pull کنید و سپس نصب‌کننده را با --managed اجرا کنید.
اگر پیام کلید ضعیف دریافت شد، فایل .env را روی همان سرور به‌صورت خصوصی اصلاح کنید.
کلید Fernet یا رمزهای مدیر را برای رفع خطای نصب تصادفی عوض نکنید.
اگر patcher تغییر محلی ناشناخته دید، آن را به زور بازنویسی نکنید؛ ابتدا تغییر را بررسی و حفظ کنید.

## شواهد این مرحله
پیش‌بررسی فقط‌خواندنی patcher روی سورس مبنا موفق شد: ۱۰ فایل هدف با anchorهای مطابق و خروجی Python قابل parse.
نحو Bash و Python و whitespace تغییرات بررسی شدند.
تست رفتاری جدید و نصب روی VPS در این مرحله اجرا نشده‌اند؛ ارسال کد به مخزن به معنی اعمال روی VPS نیست.
