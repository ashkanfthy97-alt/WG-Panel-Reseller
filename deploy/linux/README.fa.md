# راهنمای نصب و راه‌اندازی WG Portal از وب

تاریخ: ۲۰ اکتبر ۲۰۲۶. مرجع اجرایی WG_Panel در commit `f0f41068e1fd453d17acad23b9b90bc2a284bf59`.

## ۱. پیش‌نیاز و نصب

VPS با Ubuntu 24.04 x86_64، systemd، Python 3.12، دسترسی root و اینترنت برای دریافت بسته‌ها لازم است. نصب روی توزیع/معماری دیگر فعلاً پشتیبانی نمی‌شود. کلون خصوصی باید پیش از نصب با مجوز GitHub انجام شده باشد؛ خطای `Permission denied (publickey)` مشکل مجوز خواندن مخزن است.

از ریشهٔ مخزن فقط اجرا کنید:

```bash
bash deploy/linux/install.sh
```

نصب مدیریت‌شده پیش‌فرض است و Docker لازم ندارد. نصب‌کننده وابستگی‌ها، محیط Python، نسخهٔ ثابت WG_Panel و سرویس‌ها را می‌سازد. فقط توکن انتخابی ثبت نخستین مدیر (حداقل ۳۲ نویسه) را پنهان از ترمینال می‌گیرد. از رمز عبور یا توکن ربات به‌عنوان این کد استفاده نکنید. نصب مجدد تنظیمات و داده‌ها را پاک نمی‌کند و توکن موجود را خودکار عوض نمی‌کند.

کد نصب باید در مسیر root-owned و غیرقابل‌نوشتن برای کاربران دیگر باشد؛ مسیر یا تغییر محلی ناشناخته به‌جای بازنویسی رد می‌شود. نصب‌کننده سرویس یا listener نامرتبط را متوقف نمی‌کند. اجرای installer روی VPS یک عملیات واقعی نصب است؛ تست محلی جای آن را نمی‌گیرد.

## ۲. بازکردن IP و ساخت مدیر

پس از نصب، آدرس `https://SERVER_IP:8767/setup` و اثرانگشت گواهی نمایش داده می‌شود. نصب نخست از گواهی محلی دارای نام IP استفاده می‌کند و مرورگر هشدار خواهد داد. اثرانگشت را با خروجی سرور تطبیق دهید. اطلاعات محرمانه را در HTTP وارد نکنید؛ صفحهٔ HTTP تنها لینک ورود امن را نشان می‌دهد.

در فرم وب، توکن نصب، نام کاربری مدیر، رمز و تکرار رمز را وارد کنید. مدیر در جدول بومی WG_Panel ساخته می‌شود؛ افزونه حساب مدیر دوم نمی‌سازد. پس از ساخت نخستین مدیر، مسیر ثبت حساب با توکن بسته می‌شود. ورودهای بعدی از `/login` و با رمز/2FA هستند. رمز یا کلید واقعی در مخزن ثبت نشده است.

## ۳. مدیریت اتصال، دامنه و HTTPS

بعد از ورود مدیر، `/manage` را باز کنید. بدون SSH می‌توانید:

- وضعیت هسته و گواهی را ببینید؛
- گواهی عمومی برای IP درخواست کنید؛
- دامنه‌ای که DNS آن به VPS اشاره می‌کند ثبت و گواهی دامنه درخواست کنید؛
- Interface وایرگارد بسازید؛
- تنظیمات، توکن و مدیران ربات تلگرام را ذخیره، اتصالش را بررسی و سرویس همین نصب را شروع کنید.

صدور با Certbot اختصاصی محصول و پوشه‌های اختصاصی ACME انجام می‌شود. دریافت گواهی از اینترنت به دسترسی HTTP-01 روی پورت ۸۰، DNS صحیح و شرایط CA وابسته است. اگر ۸۰ آزاد نباشد، راهنمای اولیه روی ۸۷۶۸ اجرا می‌شود؛ صدور خودکار تا اتصال challenge پورت ۸۰ در reverse proxy موجود قابل تکمیل نیست. پورت ۴۴۳ به سرویس دیگر واگذار می‌ماند. گواهی IP کوتاه‌عمر است؛ timer اختصاصی هر شش ساعت تمدید را بررسی می‌کند. [مرجع رسمی Certbot و IP certificate](https://letsencrypt.org/2026/03/11/shorter-certs-certbot).

گواهی تازه ابتدا با وضعیت pending پذیرفته می‌شود. helper ثابت محصول پس از restart و بررسی اتصال TLS نتیجه را applied می‌کند. شکست اعمال با بازگردانی انتخاب گواهی و تنظیمات پیشین ثبت می‌شود؛ شکست بازیابی باید توسط مدیر بررسی شود و موفقیت نمایش داده نمی‌شود. پس از تغییر گواهی ممکن است مرورگر نیاز به اتصال تازه داشته باشد.

DNS در پنل ثبت‌کنندهٔ دامنه تغییر می‌کند. قواعد شبکهٔ ارائه‌دهندهٔ VPS و نصب agent روی VPS دیگر به دسترسی همان سرویس نیاز دارند؛ این پنل به آن‌ها دسترسی خودکار ندارد.

## ۴. پنل اصلی و نمایندگی

پس از تکمیل راه‌اندازی، `/` داشبورد بومی است. `/users`، `/subscriptions`، `/nodes`، `/backup`، `/settings` و دیگر مسیرهای upstream با فرم‌ها و APIهای اصلی حفظ می‌شوند. `/welcome` فقط صفحهٔ معرفی تصویری قدیمی است و محل مدیریت داده نیست. `/app.html` به داشبورد واقعی هدایت می‌شود.

مدیر در `/resellers` حساب نماینده، Interfaceهای مجاز و سقف مشتری را تعیین و اعتبار ماهانه را تمدید می‌کند. نماینده از `/reseller` وارد می‌شود و فقط Peerهای ثبت‌شدهٔ خودش را می‌بیند. ساخت Peer، محدودیت حجم/زمان، دریافت کانفیگ و QR، توقف/ادامهٔ بدون صفرکردن مصرف پیاده‌سازی شده است. امکانات مدیریت زیرساخت، Node و تنظیمات عمومی نزد مدیر مادر می‌ماند؛ نماینده API key یا نشست مادر را دریافت نمی‌کند.

انقضا یا توقف اعتبار، دسترسی نماینده را متوقف می‌کند؛ منابع مشتریان پاک نمی‌شوند. تمدید، دسترسی همان حساب و منابع را برمی‌گرداند. نتیجهٔ نامشخص ساخت، خودکار تکرار نمی‌شود و در عملیات در انتظار بررسی مدیر نمایش داده می‌شود. رسید درخواست تمدید از شارژ دوباره در retry جلوگیری می‌کند. پرداخت و شارژ خودکار درگاه جزو این تغییر نیست.

تم سرمه‌ای/آبی روی صفحات واقعی اعمال می‌شود. زبان پوسته، راه‌اندازی و نمایندگی فارسی/انگلیسی است؛ ترجمهٔ همهٔ متن‌های صفحات قدیمی هنوز کامل نیست.

## ۵. سرویس‌ها، پورت‌ها و داده‌ها

| جزء | سرویس/مسیر | دسترسی |
|---|---|---|
| WG_Panel بومی | `wg-panel.service`، `vendor/WG_Panel` | loopback 8766 |
| دروازه و افزونهٔ نمایندگی | `wg-portal.service` | loopback 8765 |
| HTTPS و راه‌اندازی وب | `wg-portal-setup.service` | public 8767 |
| HTTP راهنما و challenge | `wg-portal-http.service` | 80 یا fallback 8768 |
| ربات تلگرام | `wg-panel-bot.service` | پس از شروع از وب |
| تمدید گواهی | `wg-portal-acme-renew.timer` | هر شش ساعت |
| بازیابی عملیات TLS قطع‌شده | `wg-portal-tls-recover.timer` | در شروع سیستم و هر دقیقه |
| دادهٔ بومی | `vendor/WG_Panel` و مسیر DB در `.env` | مدیر سیستم |
| وضعیت راه‌اندازی/نمایندگی | `runtime/setup.sqlite3`، `runtime/resellers.sqlite3` | root-private |
| گواهی‌ها و journal | `runtime/tls`، `runtime/acme-config` | root-private |
| تنظیم محیط | `runtime/setup.env`، `runtime/portal.env`، `.env` بومی | root-private |

پورت UDP Interface از فرم وب مشخص می‌شود. تغییر خودکار فایروال محلی فقط رفتار گزینهٔ بومی Interface است؛ فایروال ارائه‌دهنده باید جدا مجاز شود. پورت غیرمعمول مرز امنیتی نیست.

از DB بومی، `.env`، فایل‌های `/etc/wireguard` و کل `runtime` همراه گواهی‌ها/مالکیت نمایندگان پشتیبان امن بگیرید. backup بومی به‌تنهایی دادهٔ افزونهٔ نمایندگی و وضعیت نصب را پوشش نمی‌دهد.

## ۶. ارتقا و عیب‌یابی

از updater مستقیم upstream استفاده نکنید؛ تغییرات محصول را بازنویسی می‌کند و عمداً مسدود است. پس از گرفتن نسخهٔ بازبینی‌شدهٔ همین محصول، همان دستور installer اجرا می‌شود. قبل از ارتقای واقعی، backup کامل بگیرید. patcher فایل با تغییر ناشناخته را رد می‌کند.

`wgportal` میانبر کمکی وضعیت/راهنما است و برای راه‌اندازی روزمره الزامی نیست. منوی اصلی upstream برای عیب‌یابی باقی است؛ تنظیم محصول از مرورگر انجام می‌شود. تغییر خطاهای سیستم، نصب Node راه‌دور یا بازیابی سرویس خارج از دسترس همچنان ممکن است به SSH نیاز داشته باشد.

برای گزارش خطا، وضعیت سرویس‌های بالا و پاسخ محلی `http://127.0.0.1:8765/login` را بررسی کنید. محتوای `.env`، توکن، رمز، private key یا cookie را در خروجی گزارش ارسال نکنید. بازنبودن IP عمومی ابتدا با firewall و سرویس HTTPS بررسی شود؛ ۸۷۶۵ عمداً روی اینترنت گوش نمی‌دهد.

این نسخه فقط نصب `managed` را پشتیبانی می‌کند. گزینهٔ قدیمی `--existing-port` با خطای روشن متوقف می‌شود: پنل موجود بدون patch محصول، قرارداد مالکیت نمایندگان و سرویس ربات این نصب را ندارد. نصب تازه حساب قبلی یا داده‌های نصب دیگر را حذف نمی‌کند؛ سرویس هم‌نام نامرتبط نیز حفظ و به‌جای تصاحب، خطا گزارش می‌شود.

## وضعیت اعتبارسنجی

تست‌های محلی فقط SQLite موقت، پاسخ جعلی native و عملیات سرویس/ACME mock را به کار می‌برند. نصب روی Ubuntu واقعی و استقرار روی VPS در این بررسی انجام نشده است. عملکرد شبکه، CA، systemd، NAT و WireGuard باید در VPS آزمایشی تأیید شود. انتقال سورس به مخزن خصوصی، تأیید عملیاتی نصب محسوب نمی‌شود.
