# نصب لینوکسی WG Portal

این بسته صفحهٔ معرفی دو‌زبانه در `/` و پنل تیره در `/app.html` را کنار نسخهٔ واقعی WG_Panel اجرا می‌کند. نمای کلی، نمودار مصرف تجمعی و فهرست Peerها بعد از ورود، داده را از WG_Panel می‌خوانند. عملیات کامل WireGuard از مسیر `/users` همان پنل در دسترس است. بخش نمایندگی، پرداخت و ثبت سفارش هنوز به سرویس فروش متصل نشده و در حالت لینوکس به‌عنوان دادهٔ واقعی نمایش داده نمی‌شود.

## دریافت مخزن خصوصی و خطای `Permission denied (publickey)`

اگر `git clone git@github.com:ashkanfthy97-alt/WG-Panel-Reseller.git` خطای بالا را نشان داد، VPS برای خواندن این مخزن خصوصی مجوز SSH ندارد. پرسش مربوط به اثرانگشت `github.com` فقط برای تأیید هویت GitHub است و به مخزن دسترسی نمی‌دهد. در نتیجه پوشهٔ `WG-Panel-Reseller` ساخته نشده و خطاهای بعدی `cd` و `install.sh` پیامد همان شکست اول هستند.

روی VPS، با کاربر `root`، یک کلید جدا برای این مخزن بسازید. اگر فایل `/root/.ssh/wg_portal_deploy` از پیش وجود دارد، آن را بازنویسی نکنید؛ کلید عمومی موجود را بررسی کنید یا نام دیگری برگزینید.

```bash
install -d -m 700 /root/.ssh
ssh-keygen -t ed25519 -f /root/.ssh/wg_portal_deploy -C "wg-portal-vps" -N ''
chmod 600 /root/.ssh/wg_portal_deploy
cat /root/.ssh/wg_portal_deploy.pub
```

متن خروجی دستور `cat` را در [Settings → Deploy keys همین مخزن](https://github.com/ashkanfthy97-alt/WG-Panel-Reseller/settings/keys) با عنوان دلخواه ثبت کنید و گزینهٔ **Allow write access** را خاموش بگذارید. کلید خصوصی را در GitHub، پیام‌رسان یا این مخزن نگذارید. کلید بدون رمز برای نصب غیرتعاملی است و فقط `root` باید به فایل آن دسترسی داشته باشد.

ابتدا دسترسی به مخزن را بررسی کنید؛ خروجی موفق `ls-remote` باید شناسهٔ commit را کنار `HEAD` نشان دهد:

```bash
GIT_SSH_COMMAND='ssh -i /root/.ssh/wg_portal_deploy -o IdentitiesOnly=yes' git ls-remote git@github.com:ashkanfthy97-alt/WG-Panel-Reseller.git HEAD
```

سپس مخزن را دریافت و یکی از روش‌های بخش ۲ را اجرا کنید. اتصال دستورها با `&&` مانع اجرای `cd` و نصب در صورت شکست دریافت مخزن می‌شود:

```bash
GIT_SSH_COMMAND='ssh -i /root/.ssh/wg_portal_deploy -o IdentitiesOnly=yes' git clone git@github.com:ashkanfthy97-alt/WG-Panel-Reseller.git && bash WG-Panel-Reseller/deploy/linux/install.sh --managed
```

برای نصب کنار پنل موجود، `--managed` را با `--existing-port PORT` و پورت واقعی محلی عوض کنید. اگر `ls-remote` همچنان `Permission denied (publickey)` داد، مطمئن شوید کلید عمومی ثبت‌شده همان خروجی فایل `.pub` روی **همین VPS** است و Deploy key در **همین مخزن** ثبت شده است. برای به‌روزرسانی بعدی نیز هنگام `git pull` همان `GIT_SSH_COMMAND` را به کار ببرید.

اگر مخزن قبلاً در `/root/WG-Panel-Reseller` دریافت شده است، از هر پوشه‌ای روی همان VPS این یک خط را اجرا کنید:

```bash
GIT_SSH_COMMAND='ssh -i /root/.ssh/wg_portal_deploy -o IdentitiesOnly=yes' git -C /root/WG-Panel-Reseller pull --ff-only && bash /root/WG-Panel-Reseller/deploy/linux/install.sh --managed
```

## ۱. اطلاعات و پیش‌نیازهای سرور

- یک VPS Ubuntu/Debian با دسترسی `root`، Git و IP عمومی ثابت. اسکریپت بسته‌های WireGuard و Python را خودش با `apt` نصب می‌کند و سرویس‌ها را با `systemd` راه می‌اندازد؛ Docker لازم نیست. برای نصب تازهٔ WG_Panel باید امکان مدیریت `/etc/wireguard` و ماژول‌های کرنل وجود داشته باشد.
- یک زیردامنهٔ اختصاصی برای پرتال، رکورد DNS نوع A و در صورت استفاده از IPv6 رکورد AAAA، و یک reverse proxy دارای HTTPS روی همان سرور. نصب‌کننده هیچ سرویسی روی پورت ۴۴۳ بالا نمی‌آورد.
- پورت‌های پیش‌فرض فقط روی `127.0.0.1` هستند: پرتال `8765` و WG_Panel نصب‌شده `8766`. n8n و ورودی HTTPS موجود دست‌نخورده می‌مانند.
- یک پورت UDP جدا برای Interface وایرگارد (برای نمونه `51820/udp`) باید مطابق تنظیم خود WG_Panel و فایروال باز شود. پورت‌های محلی `8765` و `8766` نباید از اینترنت قابل دسترسی باشند.
- پیش از نصب، از داده‌های پنل قبلی و فایل‌های `/etc/wireguard` نسخهٔ پشتیبان بگیرید. این نصب‌کننده پنل موجود را در حالت `--existing-port` تغییر نمی‌دهد.

## ۲. انتخاب روش نصب

### اتصال به WG_Panel موجود

اگر WG_Panel از قبل روی همین VPS اجرا می‌شود و از `127.0.0.1:8000` قابل دسترسی است، از ریشهٔ پوشهٔ خانگی اجرا کنید:

```bash
bash WG-Panel-Reseller/deploy/linux/install.sh --existing-port 8000
```

پورت نمونه را با پورت واقعی پنل عوض کنید. نصب‌کننده WG_Panel موجود را تغییر نمی‌دهد و صرفاً پرتال را با پروکسی محلی اجرا می‌کند. اگر پنل روی میزبان دیگری است، ابتدا تونل یا پروکسی امن محلی برقرار کنید؛ این نصب‌کننده تنها به یک پورت محلی وصل می‌شود.

### نصب تازهٔ WG_Panel

```bash
bash WG-Panel-Reseller/deploy/linux/install.sh --managed
```

اسکریپت بسته‌های لازم را با `apt` نصب می‌کند، نسخهٔ مشخص‌شدهٔ مخزن رسمی [WG_Panel](https://github.com/Azumi67/WG_Panel) را دریافت می‌کند، محیط مجازی Python و `.env` را در پوشهٔ خود WG_Panel می‌سازد، فایل‌های `instance/panel_settings.json` و `instance/runtime.json` را آماده می‌کند و دو سرویس `wg-panel.service` و `wg-portal.service` را راه می‌اندازد. کلیدهای پنل در `deploy/linux/vendor/WG_Panel/.env` خصوصی می‌مانند؛ آن را به Git اضافه نکنید. نسخهٔ مبنا `f0f41068e1fd453d17acad23b9b90bc2a284bf59` است و مجوز Apache-2.0 آن در کد دریافت‌شده حفظ می‌شود.

برای تغییر پورت‌ها: `bash WG-Panel-Reseller/deploy/linux/install.sh --managed --panel-port 8866 --portal-port 8865`. هیچ‌کدام را با سرویس‌های موجود یکسان انتخاب نکنید. روش نصب بومی Python و systemd و سازوکار اولیهٔ ادمین از مخزن رسمی WG_Panel گرفته شده‌اند. بعد از نصب، فرمان `wgportal` منوی مدیریت سایت و فرمان `wgpanel` منوی اصلی WG_Panel را باز می‌کند. اگر `wgpanel` از نصب دیگری روی سرور موجود باشد، نصب‌کننده آن را بازنویسی نمی‌کند؛ گزینهٔ «Open the complete upstream WG_Panel menu» در `wgportal` همچنان منوی نسخهٔ همراه پروژه را باز می‌کند. فرمان `wg` متعلق به خود WireGuard است و تغییر نمی‌کند.

## ۳. ساخت تنها حساب مدیر اصلی

در نصب تازه، WG_Panel فقط تا پیش از ایجاد نخستین `AdminAccount` صفحهٔ `/register` را باز می‌کند و `SETUP_TOKEN` تولیدشده در `.env` را برای ثبت‌نام می‌خواهد. پس از ایجاد نخستین حساب، درخواست‌های `/register` به ورود هدایت می‌شوند. این پروژه هیچ حساب مدیر دیگری ایجاد نمی‌کند.

پیش از انتشار دامنه، از رایانهٔ خود یک تونل موقت برقرار کنید:

```bash
ssh -L 8765:127.0.0.1:8765 root@SERVER_IP
```

این دستور را **روی رایانهٔ خود** اجرا و پنجرهٔ SSH را باز نگه دارید. سپس `http://127.0.0.1:8765/` و `http://127.0.0.1:8765/register` را در مرورگر همان رایانه باز کنید. چون سرویس روی `127.0.0.1` سرور گوش می‌دهد، آدرس `http://SERVER_IP:8765` تا زمان تنظیم reverse proxy یا تونل SSH باز نمی‌شود. نام کاربری مدیر را `ashkanfthy97@gmail.com` بگذارید و رمز را در فرم ثبت‌نام وارد کنید. مقدار `SETUP_TOKEN` را فقط از فایل خصوصی `/root/WG-Panel-Reseller/deploy/linux/vendor/WG_Panel/.env` روی سرور بخوانید. رمز را در کد، GitHub، فایل `.env`، تاریخچهٔ shell یا پیام‌ها ذخیره نکنید. هنگام ثبت‌نام یا بلافاصله پس از آن، TOTP و کدهای بازیابی را فعال و کدها را در جای امن نگهداری کنید. رمز ارسال‌شده در گفت‌وگو را پیش از دسترسی عمومی با رمز تازهٔ منحصربه‌فرد جایگزین کنید.

اگر به پنل **موجود** وصل می‌شوید، این مراحل ثبت‌نام را تکرار نکنید. ابتدا فهرست حساب‌های مدیر همان پنل را بررسی کنید و تنها پس از اطمینان از مالکیت حساب فعلی، تصمیم بگیرید آیا انتقال حساب یا پاک‌سازی لازم است. این بسته به‌طور خودکار حساب‌های موجود را حذف نمی‌کند.

## ۴. اتصال دامنه و انتشار امن

رکورد DNS زیردامنه را به IP سرور اشاره دهید. در reverse proxy موجود، همان زیردامنه را با گواهی معتبر HTTPS به `http://127.0.0.1:8765` هدایت کنید؛ مسیرهای `/users`، `/login` و `/api` هم باید از همان مبدأ عبور کنند. از ایجاد یک listener جدید روی `443` خودداری کنید اگر n8n یا سرویس دیگری آن را در اختیار دارد. بعد از فعال‌سازی HTTPS، در نصب مدیریت‌شده `SECURE_COOKIES=1` را در `deploy/linux/vendor/WG_Panel/.env` تنظیم و `systemctl restart wg-panel.service` را اجرا کنید. دسترسی `/users` و API از همان مبدأ عبور می‌کند و احراز هویت WG_Panel برقرار می‌ماند. WG Portal هیچ کلید API پنل را به مرورگر نمی‌فرستد.

قبل از در دسترس قراردادن دامنه، فقط پورت‌های لازم را در فایروال مجاز کنید، ورود SSH را به کلید محدود کنید، حساب مدیر و TOTP را بررسی کنید، گواهی TLS و نسخهٔ پشتیبان بازیابی‌پذیر را تأیید کنید. پورت غیرمعمول به‌تنهایی امنیت ایجاد نمی‌کند؛ کنترل دسترسی و HTTPS مهم هستند.

## ۵. راه‌اندازی WireGuard و ربات

پس از ورود به `/users`، Interface و پورت UDP را طبق راهنمای خود WG_Panel بسازید، آدرس شبکهٔ خصوصی، DNS و مسیر خروجی را مطابق VPS تنظیم کنید، سپس Peer آزمایشی بسازید و وضعیت اتصال و مصرف را در `/app.html` ببینید. برای اتصال Nodeهای دیگر از دستورهای رسمی WG_Panel استفاده کنید؛ کلیدهای Node را در مخزن قرار ندهید.

ربات تلگرام WG_Panel در سرویس اختیاری `wg-panel-bot.service` تعریف شده و با نصب پیش‌فرض فعال نمی‌شود. پس از ساخت ربات در BotFather، توکن را فقط در `deploy/linux/vendor/WG_Panel/.env` سرور وارد کنید، شناسه‌های مجاز ادمین را در تنظیمات خود WG_Panel تعیین کنید و سپس `systemctl enable --now wg-panel-bot.service` را اجرا کنید. رابط نماینده و سفارش سایت هنوز به ربات فروش وصل نشده است.

برای نسخهٔ فروش عملیاتی هنوز احراز هویت و مالکیت نماینده، دفتر اعتبار، سفارش‌های قابل حسابرسی، پرداخت و اتصال امن ربات تلگرام باید ساخته شوند. این بسته برای فروش واقعی آن بخش‌ها آماده نیست.
