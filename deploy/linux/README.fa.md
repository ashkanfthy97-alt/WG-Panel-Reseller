# نصب لینوکسی WG Portal

این بسته صفحهٔ معرفی دو‌زبانه در `/` و پنل تیره در `/app.html` را کنار نسخهٔ واقعی WG_Panel اجرا می‌کند. نمای کلی، نمودار مصرف تجمعی و فهرست Peerها بعد از ورود، داده را از WG_Panel می‌خوانند. عملیات کامل WireGuard از مسیر `/users` همان پنل در دسترس است. بخش نمایندگی، پرداخت و ثبت سفارش هنوز به سرویس فروش متصل نشده و در حالت لینوکس به‌عنوان دادهٔ واقعی نمایش داده نمی‌شود.

## پیش‌نیاز

- Linux با WireGuard و Docker Engine + Docker Compose v2؛ برای نصب تازهٔ WG_Panel به دسترسی لازم برای مدیریت WireGuard نیاز است.
- یک HTTPS reverse proxy موجود یا تونل SSH برای دسترسی. نصب‌کننده هیچ سرویسی روی پورت ۴۴۳ بالا نمی‌آورد.
- پورت‌های پیش‌فرض فقط روی `127.0.0.1` هستند: پرتال `8765` و WG_Panel نصب‌شده `8766`. n8n و ورودی HTTPS موجود دست‌نخورده می‌مانند.

## اتصال به WG_Panel موجود

اگر WG_Panel از قبل روی همین VPS اجرا می‌شود و از `127.0.0.1:8000` قابل دسترسی است:

```bash
cd deploy/linux
./install.sh --existing-port 8000
```

پورت نمونه را با پورت واقعی پنل عوض کنید. نصب‌کننده WG_Panel موجود را تغییر نمی‌دهد و صرفاً پرتال را با پروکسی محلی اجرا می‌کند. اگر پنل روی میزبان دیگری است، ابتدا تونل یا پروکسی امن محلی برقرار کنید؛ این نصب‌کننده تنها به یک پورت محلی وصل می‌شود.

## نصب تازهٔ WG_Panel

```bash
cd deploy/linux
./install.sh --managed
```

اسکریپت نسخهٔ مشخص‌شدهٔ مخزن رسمی [WG_Panel](https://github.com/Azumi67/WG_Panel) را دریافت می‌کند، کلیدهای نصب را در فایل خصوصی `.env` می‌سازد و پنل و پرتال را با Docker Compose اجرا می‌کند. فایل `.env` را به Git اضافه نکنید. نسخهٔ مبنا `f0f41068e1fd453d17acad23b9b90bc2a284bf59` است و مجوز Apache-2.0 آن در کد دریافت‌شده حفظ می‌شود.

برای تغییر پورت‌ها: `./install.sh --managed --panel-port 8866 --portal-port 8865`. هیچ‌کدام را با سرویس‌های موجود یکسان انتخاب نکنید. برای ورود اولیه، راهنمای راه‌اندازی WG_Panel و مقدار `SETUP_TOKEN` در `.env` را در خود سرور بخوانید؛ این توکن را در مرورگر عمومی یا مخزن منتشر نکنید.

## انتشار امن

پورت پرتال را عمومی نکنید. همان reverse proxy دارای TLS را به `127.0.0.1:8765` وصل کنید و پس از فعال‌سازی HTTPS، `SECURE_COOKIES=1` را در `.env` تنظیم و سرویس را راه‌اندازی مجدد کنید. دسترسی `/users` و API از همان مبدأ عبور می‌کند و احراز هویت WG_Panel برقرار می‌ماند. WG Portal هیچ کلید API پنل را به مرورگر نمی‌فرستد.

برای نسخهٔ فروش عملیاتی هنوز احراز هویت و مالکیت نماینده، دفتر اعتبار، سفارش‌های قابل حسابرسی، پرداخت و اتصال امن ربات تلگرام باید ساخته شوند. این بسته برای فروش واقعی آن بخش‌ها آماده نیست.
